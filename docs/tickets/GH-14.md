## Build notes

- Parse the brief with `generateText({ model: bulkModel(), output })` on a lenient schema (no bounds), then map it to `TripBriefSchema`. A brief without destination or guests gets a friendly 200, not an error.
- To stay under 10 s: put up to 30 candidates with short facts in the user message as JSON, use tools only to widen the search, and set `effort: "low"` and `maxSteps: 4`.
- Stream steps as NDJSON (`{type: "step"}` lines from `onToolExecutionStart`, then `{type: "result"}`), or just show the live feed next to the results.
- `factKey` is `fact:<key>`, `field:<column>` or `amenity:<key>`, checked in code; drop reasons that don't resolve. Don't wrap tools in `withEvent`: they would log twice (D-011).

## Goal

The guest describes the trip in their own words and the guest agent returns a shortlist with reasons that cite real facts. This is the first "AI decides, not filters" moment of the demo.

**Owner:** Beka · **When:** hours 7–9 · **Estimate:** 2.5–3h · **Depends on:** GH-8, GH-9 (X-ray facts), GH-13 · **Blocks:** nothing (demo step 1)

## Build

### 1. Input

- The trip brief box on `/search`: a textarea plus a mic button using the browser Web Speech API.
- Demo brief: _"4 friends, Kazbegi or Tbilisi, early November, about $60 each per night, one of us works remotely, we want a fireplace or a cozy living room and a mountain view."_

### 2. `POST /api/search` (streaming)

1. **Parse** with `MODEL_BULK` into a Zod `TripBrief`: destination(s), dates, nights, guests, budget per night or total, must-haves, nice-to-haves, deal-breakers, work needs, pets, accessibility. Save to `trip_briefs`.
2. **Pre-filter in SQL:** city, `max_guests >= guests`, availability for the dates, price up to 1.2 × budget (room to negotiate). Keep at most 30 candidates.
3. **Rank** with the guest agent (`createAgent`, `MODEL_AGENT`) and tools `search_listings(filters)` and `get_listing_facts(listingId)`. The agent may widen the area or relax one nice-to-have, and must say so.
4. **Output** (Zod): `[{listingId, score 0–100, reasons: [{text, factKey}], concerns: [{text, factKey?}], negotiationHint?}]`. Each reason must cite an X-ray fact key or a listing field; drop any reason without one.

### 3. UI

- Ranked cards. The top card is highlighted, with 3 reason chips (e.g. "Desk near window: seen in photo 4") and concerns in amber.
- A "Why not the others" collapsible list.
- Live agent steps while it works ("Checking 23 homes…", "Widened to Kazbegi + Gudauri").

### 4. Events

"Guest agent shortlisted 5 homes for Nino's brief", plus one event per tool call via `withEvent`.

## Acceptance criteria

- [ ] The demo brief returns a hero home first, with 3 cited reasons, in under 10 seconds.
- [ ] Every shown reason maps to a real fact or field; no invented amenities.
- [ ] Voice input works in Chrome on desktop.
- [ ] Results and steps show in the activity feed.
- [ ] An empty or odd brief gets a helpful message, not an error.
