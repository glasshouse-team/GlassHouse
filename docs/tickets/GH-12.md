## Goal

"Everyone can see who did what" is a literal Track 01 requirement. Every agent tool call and human action appears in a live feed within 2 seconds.

**Owner:** Beka · **When:** hours 5–6 · **Estimate:** 1h · **Depends on:** GH-5 (`events` table, `logEvent`) · **Blocks:** nothing, but every feature writes to it

## Build

### 1. `lib/events.ts`

`logEvent()` is already defined in GH-5. Make sure it:

- Writes server-side with the service role and never throws into the caller (log the error and continue).
- Truncates `summary` to 140 characters and keeps the full detail in `payload`.

### 2. `tools/_withEvent.ts`

A wrapper `withEvent(toolName, agent, fn)` that logs every tool call automatically: start, result summary, errors. All agent tools from GH-13 use it. Temuri's Verifier tools use it too (read-only import).

### 3. `components/feed/ActivityFeed.tsx`

- Props: `filter: 'listing' | 'deal' | 'all'`, `listingId?`, `dealId?`, `compact?`.
- Loads the last 50 events, then subscribes to Supabase Realtime `INSERT` on `events` with the same filter.
- Each row shows an actor icon and color (guest agent, host agent, Verifier, human, system), the summary, and a relative time ("12s ago").
- Clicking a row opens a drawer with the payload JSON.
- New rows slide in at the top; rows are grouped by deal when `filter='deal'`.

### 4. Full-screen projector view `/feed`

Large text and dark mode, for the stage demo.

### 5. Placement

Listing page sidebar (`filter='listing'`), deal room (`filter='deal'`), host dashboard (`filter='all'` for the host's listings).

## Acceptance criteria

- [ ] Insert a test event; it appears in an open browser within 2 seconds without a refresh.
- [ ] The colors and icons tell the 5 actor types apart at a glance.
- [ ] `withEvent` is used by at least one real tool (search or X-ray) before closing.
- [ ] `/feed` is readable from 5 meters away on a projector.
