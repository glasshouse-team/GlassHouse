## Goal

The strongest Track 01 moment. The guest says "Can I pay $50 less?", the two agents negotiate live in a visible deal room, the code enforces the host's limits, and the host's one tap books it.

**Owner:** Beka · **When:** hours 9–13 · **Estimate:** 4h · **Depends on:** GH-7 (hero policy), GH-8, GH-12, GH-13 · **Blocks:** GH-17 (MVP checkpoint)

## Deal states

`open` → offers/counters → `agreed_pending_host` (between floor and auto-accept) **or** `approved` (at or above auto-accept) → reservation.
Side exits: `declined`, `escalated` (an agent hands over to a human), `expired` (`max_rounds` reached).

## Build

### 1. Open a deal

"Negotiate" on the listing page opens a sheet with dates, guests, "What would you like to pay?" (target) and "Most you'd pay" (private).
`POST /api/deals` creates `deals` (list total from `computeQuote`) and `deal_secrets`, then logs an event.

### 2. Tools (`tools/negotiation/`)

- `make_offer(amountCents, terms, reason)`
- `accept_offer()`
- `decline(reason)`
- `escalate_to_host(reason)` (host agent)
- `ask_guest(question)` (guest agent)

Every money tool calls `validateOffer` (GH-13) **before** saving. A rejection is returned to the agent as a tool error with the reason, so it must try again.

### 3. Run loop `POST /api/deals/[id]/run`

- Alternate turns: the guest agent (context = `buildGuestContext`), then the host agent (context = `buildHostContext(…, 'negotiate')`).
- Each turn stops after **one** money action. Each message is saved to `deal_messages` and pushed via Realtime.
- Pause 1.5 s between turns in demo mode so people can read.
- Stop on accept, decline, escalate or `max_rounds`.

### 4. Acceptance logic

- Host accepts at or above `auto_accept_total_cents` → `approved` → create the reservation immediately.
- Host accepts between the floor and auto-accept → `agreed_pending_host` → appears in the host's **Approvals queue** with a toast: "Approve $480 for Nov 6–10 (−$40, 7.7% off)?"
- Host taps **Approve** → `POST /api/deals/[id]/approve` creates a `reservations` row with the discount line, sets `approved`, logs an event, and the guest sees "Booked". **Decline** sets `declined`.

### 5. Deal room UI `/deal/[id]` (`components/deal/`)

- A timeline of offer cards: actor, amount, difference from list, reason; validator rejections shown as small grey notes.
- A status pill, and the activity feed filtered to this deal.
- Guest controls: "Stop", "Accept last offer". Host controls (role switcher): "Approve", "Decline", "Counter myself".

## Test fixture: the demo script

Hero home 1, 4 nights for 2 guests, list total $520 (4 × $120 + $40 cleaning). Effective floor $442; auto-accept $490. Guest target −$50, max $500.

| Round | Actor | Action | Expected check |
| --- | --- | --- | --- |
| 1 | Guest agent | offer $470 ("4 nights midweek, low season") | valid |
| 2 | Host agent | counter $495 | ≥ $442 floor ✓ |
| 3 | Guest agent | counter $480 | ≤ $500 guest max ✓ |
| 4 | Host agent | accept $480 → `agreed_pending_host` | < $490 auto-accept |
| 5 | Host (human) | Approve | reservation: $480 + $40 cleaning, −$40 discount, + service fee |

## Branch tests (all must pass)

- [ ] **Lowball:** the guest offers $400; the host agent's `accept_offer` is **refused** by the validator, so it counters ≥ $442 or declines.
- [ ] **Not negotiable:** `negotiable = false`; the host keeps the price and offers an allowed term instead (e.g. late checkout).
- [ ] **Round limit:** after 6 rounds the deal is `expired`, and the guest can "Accept last offer".
- [ ] **Over budget:** the host's best is above the guest max; the guest agent calls `ask_guest`.
- [ ] **Instant:** an offer at or above $490 is approved without a human.
- [ ] **Secrets:** grep the logged prompts; the guest agent never saw the floor, and the host never saw the guest max.

## Acceptance criteria

- [ ] All branch tests pass.
