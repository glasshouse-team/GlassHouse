## Build notes

- Put the logic in `lib/marble-worlds.ts`: `finalizeWorld()`, `publishWorld()` and `importWorld()` (upsert on `listing_id, version`), shared by the routes, the CLI (`pnpm worlds import <world_id> --listing <id> --version <n>`) and GH-26's reset.
- Status route: `export const maxDuration = 300`; save `marble_world_id` as soon as it appears (operations expire; after that use `getWorld`); copy assets with `upsert: true`; set `ready` with `.eq("status", "generating")` and log only if a row changed.
- Leave `hq_mesh_url` null (the HQ mesh needs an export that can take an hour), and `spz_hq_url` null when `full_res` is over the plan's file limit.
- Only polling moves a world forward: WorldVersions polls the status route every 15 s while a row is `generating`. In DEMO_MODE, status and import never call World Labs.
- Hero import (part A, done 2026-10-18): `pnpm worlds --import hero-2` reads docs/hero-worlds.json, GETs each spot world (no generation), copies web splat, HQ splat, collider, pano and thumbnail into `media/worlds/{row id}/`, upserts one row per spot and publishes v2 (all 5 v2 rows `published`, `listings.published_world_id` = v2 entrance). v1 is a full 5-spot version (D-031): its 4 unchanged spots share the v2 rows' files (same URLs, `cost_credits` 0), so nothing is stored twice. Idempotent: a re-run uploads nothing and logs nothing. `pnpm worlds verify hero-2` prints the rows, HEADs every URL and measures each collider floor.
- `POST /api/captures` returns `createSignedUpload("media", "captures/{listingId}/{captureId}/prepared.mp4")`; accept prepared mp4s up to 20 MB (no server-side ffmpeg, D-015). Keep the starter's `generateWorld(request)` signature.

## Goal

Turn a walkthrough into a saved, versioned 3D world. **Generate once, store everything ourselves, never call World Labs on a page view.**

**Owner:** Temuri · **When:** hours 5–8 · **Estimate:** 3h · **Depends on:** GH-3, GH-5, GH-6 · **Blocks:** GH-11, GH-18, GH-19

## Build

### 1. `lib/marble.ts` (client)

- `generateWorld({input, model, textPrompt})` → `{operationId}`.
  - Input is `{type: 'video', uri}`, `{type: 'multi-image', images: [{uri, azimuth?}]}` or `{type: 'image', uri}`.
  - Header `WLT-Api-Key`. Model from `MARBLE_MODEL` (`marble-1.1-plus`).
- `getOperation(id)` → status and progress; `getWorld(worldId)` → assets.
- Map errors to readable messages: insufficient credits, a URL World Labs can't fetch (it must be public with no cookies), file over 20 MB.

### 2. `lib/media.ts` (ffmpeg via `ffmpeg-static`)

- `prepareVideo(raw)`: H.264, 720p, 30 fps, no audio, bitrate chosen so the file stays under 20 MB.
- `extractFrames(video, everySec)` and `joinClips([...])` for fill-ins (GH-19).

### 3. API routes (`app/api/worlds/`)

- `POST /api/worlds {listingId, captureIds}` creates the next `worlds.version` with status `generating` and stores the `operation_id`.
- `GET /api/worlds/[id]/status` checks the operation and finalizes when it is done:
  - Download the medium `.spz` (web) and the largest `.spz` (HQ), the collider mesh, the HQ mesh, the panorama and the caption into `media/worlds/{id}/`.
  - Save `metric_scale_factor` and `ground_plane_offset`.
  - Set status `ready` and log an event ("World v2 ready for <listing>").
- `POST /api/worlds/[id]/publish` sets `listings.published_world_id`, marks it `published`, archives the previous version and logs an event.

### 4. Photos-only path

2–8 photos go to Marble multi-image. 9 or more go to HY World on Scenario (only if GH-3 chose it).

### 5. Demo mode

With `DEMO_MODE=true`, `POST /api/worlds` returns the saved version immediately and never calls the API.

### 6. Import script

`scripts/generate-worlds.ts --import <world_id>` imports the 3 worlds already generated in GH-6 into storage and `worlds` rows (Hero 1 v1, Hero 1 v2, Hero 2 v1).

### 7. UI `components/tour/WorldVersions.tsx` (host dashboard slot)

A list of versions with status, progress, thumbnail, created time, a Preview link to `/tour/[listingId]?version=n`, and a Publish button.

## Acceptance criteria

- [ ] All 3 GH-6 worlds are imported; their files are served from **our** storage.
- [ ] Network logs show a tour page view makes zero calls to `api.worldlabs.ai`.
- [ ] One new generation runs end to end from the host dashboard: generating → ready → published.
- [ ] Publishing v2 switches what guests see; v1 stays archived.
- [ ] Every status change appears in the activity feed.
